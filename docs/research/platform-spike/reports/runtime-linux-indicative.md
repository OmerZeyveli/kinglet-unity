## Version Invocation Protocol Finding

The four candidates are **not protocol-consistent** on version invocation. This is itself a finding:

| Candidate | Invocation that works | Invocation that fails |
|---|---|---|
| Python | `kinglet-host-probe version` (subcommand) | `--version` (unrecognised argument) |
| Go | `kinglet-host-probe --version` (flag) | `version` (exits with usage, non-zero) |
| Rust | `kinglet-host-probe --version` (flag) | `version` (exits with usage, non-zero) |
| .NET | `kinglet-host-probe --version` (flag) | `version` (exits with usage, non-zero) |

Python accepts `version` as a positional subcommand; Go, Rust, and .NET accept `--version` as a flag.
The host-probe contract spec should pin one form before Task-7/8 gate evaluation.

## Interpretation

All four candidates pass the full 18/18 contract suite — the protocol specification is satisfied by every implementation on this host.

The cold-start numbers reveal a three-tier split. **Rust and Go** are sub-2 ms median: they link against no interpreter and pay only OS ELF-loader cost. **.NET** sits at ~24 ms median: the self-contained single-file bundle must load the CoreCLR runtime and JIT the startup path before returning. **Python** is ~312 ms median: the PyInstaller onefile format extracts its entire embedded archive to a temporary directory on every invocation before the interpreter starts. This extraction cost is real and repeatable — it does not diminish on repeated runs unless the OS's filesystem cache is warm (and even then the extraction step itself is skipped only if PyInstaller's `_MEIPASS` directory already exists, which it does not for separate cold runs). The ~300 ms figure is therefore a genuine property of the packaging strategy, not noise.

RSS and artifact size follow the same pattern. Native binaries (Go 2.9 MB RSS / 2.6 MB file; Rust 2.5 MB RSS / 0.9 MB file) are compact. The Python onefile (31.8 MB RSS / 17.3 MB file) and the .NET single-file (23.7 MB RSS / 70.3 MB file) carry their runtimes. The .NET artifact is large because the self-contained publish bundles the entire .NET 10 runtime tree into one file; the runtime footprint in RAM is more moderate (23.7 MB).

**These are single-host, non-locked-distro numbers.** Do not use them as gate evidence. The Task-7/8 evaluation on five Ubuntu 24.04.4 hosts may produce materially different absolute values, particularly for .NET (which is sensitive to JIT warmth and kernel version) and Python (where extraction time depends on the target filesystem).
